# 播放列表推送功能测试指南

## 测试目标

验证以下功能正常工作：
1. **服务端推送** - 管理后台操作后，WebSocket 推送通知到播放端
2. **播放端接收** - 播放端正确接收并处理推送消息
3. **媒体下载** - 播放端下载媒体文件并上报进度
4. **自动切换** - 下载完成后自动切换播放列表
5. **增量更新** - 播放列表更新时只下载新增的媒体

## 测试前准备

### 1. 启动后端服务

```bash
cd /Users/Davy/PycharmProjects/CastPlay/castplay-allinone
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## 测试方式一：使用测试页面

### 步骤 1：打开测试页面

在浏览器打开：
```
http://localhost:8000/test-push.html
```

### 步骤 2：确认 WebSocket 连接

测试页面会自动连接 WebSocket，观察：
- WebSocket 状态显示 "已连接"（绿色）
- 设备 ID 显示 `web-player-test-01`
- 测试检查点 1 变为 "已完成"

### 步骤 3：分配播放列表

1. 在新标签页打开管理后台：`http://localhost:8000/dashboard`
2. 进入 **设备管理** 页面
3. 找到设备 `Player-Test01`（或 `web-player-test-01`）
4. 点击 **分配播放列表**，选择一个播放列表
5. 确认分配

**预期结果**（测试页面）：
- 测试检查点 2 变为 "已完成"
- 显示收到的推送消息
- 显示播放列表信息

### 步骤 4：观察下载进度

**预期结果**：
- 测试检查点 3 显示下载进度
- 进度条动态更新
- 下载完成后状态变为 "已下载 X 个文件"

### 步骤 5：确认自动切换

**预期结果**：
- 测试检查点 4 变为 "已完成"
- 当前播放列表显示新分配的列表
- 同步状态变为 "ready"

### 步骤 6：测试增量更新

1. 在管理后台，进入 **播放列表管理**
2. 找到刚才分配的播放列表
3. 添加或删除一个媒体项
4. 保存

**预期结果**：
- 测试检查点 5 变为 "运行中" 然后 "已完成"
- 日志显示 `playlist_updated` 消息
- 显示变更内容（added/removed）

## 常见问题

### Q: 设备显示离线

**A:** 确保：
1. 测试页面已打开
2. WebSocket 连接成功
3. 后端服务正在运行

### Q: 收不到推送消息

**A:** 检查：
1. WebSocket 连接状态
2. 设备 ID 是否匹配
3. 后端日志是否有错误

### Q: 下载失败

**A:** 检查：
1. 媒体文件是否存在
2. 文件路径是否正确
3. 文件权限是否正确

### Q: 切换失败

**A:** 检查：
1. 下载是否全部完成
2. 控制台是否有错误
3. localStorage 是否有冲突数据
